# ADR-0011：覆盖率门槛的落点与多模块归属

- 状态：Accepted（2026-10-11 确认并已实施）
- 日期：2026-10-11
- 决策者：项目维护者
- 影响范围：构建配置、`mini-spring-beans` / `mini-spring-context` / `mini-spring-web`、两个样例

## 背景

JaCoCo **按模块统计**：每个模块的报告只包含该模块 `src/main` 的类，且只使用该模块自己的测试执行数据。由此产生两个在多模块项目里经常被误判的问题：

1. **"web 模块没有被测"是个假象。** `MiniHandlerMapping`、`RequestArgumentResolver`、`MiniDispatcherServlet` 其实被样例（`samples/mini-spring-standalone`）的端到端测试大量覆盖，但那部分数据不会出现在 web 模块的报告里。处理不好会有两种后果：以为 web 没被验证过；或者为了把报告"刷好看"而在 web 里重复写一遍样例已经覆盖的测试——两份测试维护同一件事，迟早漂移。
2. **样例里的 `MainApp` 不该被纳入统计。** 它是命令行报告程序，职责就是打印。为它写测试等于断言 `System.out`，收益极低而维护成本明确。

同时，上一阶段的门槛配置是**直接写在 `mini-spring-context` 的 pom 里**的。这带来一个具体隐患：要给所有库模块统一标准，就得往每个模块复制一份配置；本轮实际改门槛时就出现了"要同时改父 POM 与 context 两处"的情况——三份配置迟早漂移。

## 决策

1. **门槛只配一处**：父 POM 的 JaCoCo `check` 执行，统一 **行 85% / 分支 75%**。各模块不再重复配置。
2. **适用范围**：所有含 `src/main` 且有测试的库模块。没有类、没有执行数据的模块（聚合 POM）由 JaCoCo 自动跳过。
3. **样例显式跳过**：`samples/mini-spring-standalone` 在自己 pom 里设 `<skip>true</skip>`，理由是它是**应用**而不是库——跳过写在它的 pom 里，而不是靠全局豁免掩盖。
4. **归属原则：报告按模块归属，但覆盖来源不作限制。** web 模块的类被样例端到端覆盖是正当且经济的；web 模块自身保留架构守卫与 Servlet 层单测（初始化三条路径、404、已提交响应、异常包装、路径归一化等）。**不为"报告好看"重复测试。**
5. **门槛设在目标值而非实测值**：三个模块实测均高于门槛（见下），门槛不会因为某次删测试而形同虚设。

实测值（2026-10-11，门槛 0.85 / 0.75）：

| 模块 | 行 | 分支 |
| --- | --- | --- |
| `mini-spring-beans` | 97.8% | 87.2% |
| `mini-spring-context` | 87.2% | 78.4% |
| `mini-spring-web` | 96.1% | 90.3% |
| `samples/mini-spring-standalone` | 63.7% | 50.0%（不设门槛，见决策 3） |

## 后果

正面：

- 门槛只有一处，改标准就是改一行，不会出现"某个模块还在用旧标准"；
- 不必为了报告数字重复测试，测试的职责划分反而更清楚：库里测契约，样例里测组合；
- 样例不被无意义的断言污染（不去断言 `System.out`）；
- 与 ADR-0010 的原则一致：**每条门禁都要能说清它防的是什么问题**。

负面：

- "web 的端到端覆盖不算进 web 报告"这一点必须靠文档解释，否则后来者仍会误判（因此写在本 ADR 里，并同步到 README）；
- 统一门槛意味着不同模块的"难度"不同：`context` 的错误分支多，达标比 `beans` 难。若将来某模块因客观原因达不到，需要显式在本 ADR 里记录例外，而不是私下调低。

## 被否决的替代方案

1. **把样例的覆盖算进 web 报告**（JaCoCo 的 `report-aggregate`，或把端到端测试搬进 web 模块）：会把库与样例耦合起来，样例就不再是"使用方视角"的验证。
2. **每个模块各写一份门槛配置**：三份配置必然漂移，本轮已经出现过一次。
3. **对样例也设门槛**：会逼迫为 `MainApp` 写"断言打印内容"的测试，属于为指标写测试。
4. **不设门槛，只看报告**：那等于"看心情达标"，与 ADR-0010 里"没有自动检查的约束等于没有约束"直接冲突。

## 验收标准

1. 三个库模块在 `mvn verify` 中都输出 `All coverage checks have been met.`；
2. 样例模块不出现覆盖率检查结果（已 `skip`）；
3. 门槛数值在仓库中**只出现一处**（父 POM 的 `jacoco-check`），可用搜索验证；
4. 模块实测值记录在本 ADR 的表中，改动门槛时同步更新该表。
